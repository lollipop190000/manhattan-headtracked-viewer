# Reproducible city assets

`assets/source-manifest.json` identifies the immutable source version `manhattan-2026-10-10-v2`, private release `city-source-v2`, and exact six ZIPs. SHA-256 and byte counts cover every ZIP and every file inside it. Core/ground and procedural-source ZIPs are the corrected v2 delivery; the three near-detail ZIPs and vegetation ZIP retain their original hashes. The existing extracted files have been compared against this manifest; local additions do not change the canonical release.

V2 repairs constrained triangulation of road/sidewalk/curb/park/water/island surfaces and affected courtyard roofs/coping. Original building footprint/height data, material properties, embedded texture contents and shared coordinate origin are preserved. The source release retains its v2 triangulation and integration audit files. It still uses flat ground and procedural exterior approximations.

[The replacement audit](source-v2-audit.md) records archive fingerprints, preserved data/material evidence and revised geometry counts.

Each ZIP has relative contents without a common top directory. Setup extracts it into `3d_modeling/<ZIP stem>/`. The three near-detail ZIPs contain 243 additive GLBs. Their geometry adds raised windows/sills; it must not replace or duplicate the original building bodies. Core, ground, detail, and vegetation share one geographic origin.

## Integrity and setup

```powershell
python tools/source_assets.py validate
python tools/source_assets.py verify --archives --archive-root .cache/source-downloads
python tools/source_assets.py verify --extracted
```

Authenticated `gh release download` downloads private assets without recording tokens. Setup validates archive hashes before extraction, rejects traversal, drive/stream paths, reserved Windows names, symlinks, encrypted entries and case-aliased filenames, then verifies extracted files before publishing a completed pack directory. Rerunning accepts exact existing inputs. If an expected file changed, setup stops and preserves it: move your edited pack to a separate authoring location before downloading the canonical source again.

Keep source versions immutable. To publish an intentional update, create a new release tag/source version, generate its new manifest with `python tools/source_assets.py make-manifest --archive-root <reviewed ZIP directory> --source-version <new version> --release-tag <new tag>`, review provenance and hashes, and update the version/tag together before rerunning the bake. The generator starts from six reviewed ZIPs; it does not scrape new NYC data or run historical Blender scripts.

## Unity conversion

`tools/bake.ps1` verifies all uncompressed inputs and passes `MANHATTAN_SOURCE_ROOT` to `Manhattan.Editor.CityBake.BuildAll`. glTFast imports GLBs in the editor. Build-time meshes and shared materials/textures are extracted into independent generated assets; tile prefabs must never depend on an entire monolithic source GLB. Keep 500m logical tiles and 125m detail partitions aligned to the common origin. Imported bounds and axis conversion are authoritative.

The bake writes `Builds/city-bake.json`. `python tools/catalog_validation.py --require-full` validates source version, unique tile IDs/addresses, finite nonnegative bounds, resident-byte/triangle records, complete layer coverage and valid skyline replacements. Every skyline's `requiredReplacementCount` must equal the number of incoming Core records that replace it; zero retains an unreplaced fallback. Near/ground/vegetation layers cannot claim to replace building bodies. `tools/bake.ps1` runs this check automatically after the Unity bake.

Generated tiles are ignored under `ManhattanViewer/Assets/Generated/City`, source imports under `Assets/CitySource`, and the generated catalog at `Assets/Resources/CityCatalog.asset`. Addressables data is regenerated by the bake and is also ignored. Rebuild these from the manifest instead of committing machine-specific output. Small reviewed validation samples and team-edited binary source assets may be checked in through LFS with their stable `.meta` files. Never commit original ZIPs plus the same expanded city.

Coordinates originate in EPSG:32618 at longitude -73.97, latitude 40.78. Source Blender X/Y/Z mean east/north/up, in metres, and GLB uses Y-up. The bake retains the actual importer conversion and uses tile-local vertices to reduce floating-point jitter. Preserve original building IDs, complete rings, heights and height-estimated flags for gameplay metadata. Runtime origin shifts change rendering coordinates while geographic city coordinates remain continuous.

## Attribution

The original `PROVENANCE.md`, `NYC_Open_Data_Terms.html`, metadata and procedural authoring records remain inside the release packs. Retain them when redistributing city derivatives. The data is NYC Open Data under its original terms; it is not relabeled CC0 or public domain. Procedural facade, window and vegetation details are approximations rather than surveyed per-building imagery. Read [THIRD_PARTY.md](../THIRD_PARTY.md) and the retained provenance before using source heights or changing terrain.

The reviewed [source Release notice](source-release-notice.md) accompanies the private source assets. Manifest validation rejects a source pack that drops its original provenance or reuse terms. `tools/build.ps1` also runs `tools/package_notices.py` after a successful player build: it verifies the original notice fingerprints and copies them, viewer/tracking MIT notices, version manifests and Unity package notices into the player's `Notices/` directory. Keep that directory when zipping or redistributing a Windows build. A build invoked directly from the Editor/CLI must run this same notice command before distribution.
