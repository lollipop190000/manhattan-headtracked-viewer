# Manhattan 헤드 트래킹 뷰어의 깊이 지각 검증

검증 기록: 2026-10-10. 제품 코드 기준은 `df12acb183746aab50af6c48c728923edfce828b`, 기술 패키지는 `960d5de55037a3fe2739ed055c8de091b8c54aed`이다. [기존 회귀 테스트와 실행 조건](headtracking-diagnostics.md)은 별도 기록을 따른다.

## 결론

합성 입력을 사용한 원본 챔버 대 최소 프레임 비교와 연속 프레임 진단을 마쳤다. 검사한 투영과 가림 관계에는 근거가 생겼지만, 사람이 고개를 움직일 때 도시를 화면 너머에 고정된 공간으로 느끼는지는 아직 검증하지 않았다. **다음에는 실제 표시 영역 보정을 가장 먼저 확인하고, 가까운 기준면과 실제 도시의 움직임 단서를 검사한 뒤 짧은 사용자 A/B를 진행한다.** 표시 영역 보정은 우선 조사할 가설이며 아직 확정된 원인이 아니다.

일반 평면 모니터에서도 관찰자의 움직임에 맞는 운동 시차는 깊이 지각을 만들 수 있다. 초기 실험과 Fish Tank VR 연구도 이 효과를 다뤘다. 따라서 평면 화면이라는 이유만으로 효과를 부정하거나, 화면상 이동량만으로 지각적 성공을 선언해서는 안 된다. [Rogers와 Graham 1979](https://pubmed.ncbi.nlm.nih.gov/471676/), [Arthur 등 1993](https://scholars.unh.edu/ccom/929/)

이 검증에서는 도시의 미터 단위 스케일과 보정된 머리 이동 배율을 유지한다. 도시 전체 축소나 시차 배율 증폭은 현재 결과로 정당화되지 않는다. 실제 웹캠, 도시의 얇은 창틀과 식생, 사용자 깊이 지각은 후속 검증으로 남아 있다.

## 현재 증거와 남은 질문

| 확인 항목 | 현재 결과 | 증명하지 못하는 것 |
| --- | --- | --- |
| 기존 자동 테스트 | EditMode 63개, PlayMode 25개, 실패 0개 | 실제 관찰자의 깊이감, 장면 안정감, 사용 편안함 |
| 합성 시점의 렌더 경계 정합 | 검사한 조건에서 최대 오차 0.522 px | 실제 눈 위치와 화면의 정합, 움직이는 사람에게 보이는 안정감 |
| 기존 원본 렌더 테스트의 소스 확인 | 코드가 시점 변경 뒤 12프레임 안정화 후 캡처하도록 구성됨. 이번에 새로 실행한 측정 결과는 아님 | 연속 움직임 중 잔상, 가림이 풀리는 영역의 이력 오류 |
| 챔버 대 최소 프레임 합성 A/B | 최종 v2 진단에서 PNG 6장과 색상 마스크 30개 재확인 | 어느 구성이 사용자에게 더 깊고 안정적으로 보이는지 |
| 연속 프레임 진단 | TAA OFF 60프레임과 ON 60프레임 검사 | 실제 도시 전체의 잔상, 실제 웹캠 성능, 전체 지연 |

새 검사는 작업 사본의 임시 테스트 두 개가 각각 1/1 통과한 결과다. 기존 제품 테스트 수에 합산하지 않는다. 초기 진단 준비 과정의 큐브 조건 및 컴파일 오류를 수정한 뒤 최종 v2 결과만 유효한 결과로 사용했다. 이 진단의 제품 코드 변경이나 임시 검사 코드는 PR에 포함하지 않았다. 이 문서에는 검증 결과와 한계만 기록한다.

화면 녹화는 프레임 사이의 영상 변화와 렌더 오류를 보여 준다. 그러나 실제 머리 움직임, 눈의 회전, 물리적 화면을 함께 보는 경험은 담지 못한다. **화면 녹화만으로 움직이는 관찰자에게 장면이 세계에 고정돼 보인다고 증명할 수 없다.**

## 새 합성 진단에서 확인한 내용

### 두 구성의 차이는 가림과 보이는 영역에서 나타났다

A는 실제 `BillboardIllusionController`, B는 실제 `ScreenWindowFrame`을 그대로 사용했다. 같은 고정 큐브, 눈 위치, 렌더 해상도에서 TAA OFF와 1샘플 조건을 맞췄다. 원본 안쪽 프레임과 최소 바깥쪽 띠의 개구부 차이는 그대로 유지했다.

- A와 B의 눈 위치 및 화면 평면 기준점 차이는 0이었다.
- 광선과 상자의 교차 계산으로 예상한 영역과 색상 마스크의 불일치는 물체당 최대 8픽셀이었다. 이는 **서로 다른 픽셀의 면적 집계**이며 8 px 위치 오차가 아니다.
- 아래 수치는 중립 시점에서 해당 물체의 가시 영역과 프레임에 가려진 영역을 세어 비교한 것이다. 단위는 모두 픽셀 면적이다.

| 검사 물체 | A에서 보이는 영역 | A의 프레임 가림 | B에서 보이는 영역 | B의 프레임 가림 |
| --- | ---: | ---: | ---: | ---: |
| 안쪽의 화면 뒤 큐브 | 9,391 | 2,374 | 17,116 | 0 |
| 바깥쪽의 화면 뒤 큐브 | 0 | 2,222 | 12,958 | 2,588 |

바깥쪽 뒤 큐브는 A의 세 검사 시점 모두에서 보이지 않았다. 프레임 가림 집계는 프레임에 해당하는 부분만 세므로 전체 가림을 설명하는 값은 아니다. 화면 앞 큐브는 프레임을 올바른 순서로 덮었지만, 두 구성 모두 최종 표시 영역 가장자리에서 잘렸다. 바깥쪽 앞 큐브의 표시 영역 밖 실루엣은 투영 계산상 약 18,052픽셀 면적으로 추정됐다.

이 결과는 전체 구성에 따라 **무엇이 얼마나 보이는지가 달라진다**는 증거다. 챔버의 특정 단서가 깊이감을 높인다는 인과 검증은 아니다. 보이지 않는 물체는 사용자의 깊이 순서 시행에 넣지 않는다.

### 연속 프레임에서 큰 외곽선 잔상은 검출되지 않았지만 비교 제약이 있다

TAA OFF와 ON에 같은 입력 위치열을 주었으나 실행 타이밍은 달랐다. 합성 입력의 필터 전 위치 추정 오차는 0 mm였고, 입력과 필터 출력 사이 최대 거리는 OFF에서 13.06 mm, ON에서 15.94 mm였다. 이 값은 위치 차이이며 시간 지연 자체가 아니다. ON과 OFF가 실제 렌더에 사용한 눈 위치도 최대 4.66 mm 달랐으므로 두 이미지의 차이를 곧바로 TAA 효과로 돌릴 수 없다. 합성 입력의 0 mm 오차는 실제 웹캠 정확도를 뜻하지 않는다.

각 프레임에 실제 사용된 눈 위치로 외곽선을 계산해 검사한 결과는 다음과 같다.

- 2 px 여유 영역 밖의 이전 외곽선 잔상 검출은 0픽셀이었다.
- 여유 영역을 1 px로 줄이면 ON에서 최대 160개의 희미한 픽셀이 검출됐다.
- ON의 TAA 이력은 60프레임 모두 갱신됐다.

여유 영역과 색상 임계값은 이 검사에서 정한 공학적 검출 조건이다. 사람에게 잔상이 보이지 않는다는 지각 임계값이 아니다. 얇은 창틀, 식생, 반사, 복잡한 가림 해제를 포함한 도시 장면의 품질도 이 큐브 검사로 대신하지 않는다.

프레임별 GPU 읽기와 PNG 저장에 걸린 시간의 중앙값은 약 22~25 ms였다. 기록 작업의 비용이 섞여 있으므로 제품 FPS나 전체 motion-to-photon 지연의 벤치마크로 사용하지 않는다.

## 원본과 현재 뷰어의 중요한 차이

현재 확인된 구현 차이는 투영식 외에도 있다.

- 원본 `BillboardIllusionController`에는 안쪽 프레임, 어두운 주변부, 챔버의 바닥과 벽, 깊이가 다른 블록, 그림자가 있다. [원본 챔버 구현](https://github.com/lollipop190000/head-tracked-display/blob/960d5de55037a3fe2739ed055c8de091b8c54aed/Packages/com.headtracked.display/Runtime/BillboardIllusionController.cs#L80-L160)
- `ScreenWindowFrame`은 네 가장자리 띠로 구성된 최소 프레임이며 그림자를 사용하지 않는다. [최소 프레임 구현](https://github.com/lollipop190000/head-tracked-display/blob/960d5de55037a3fe2739ed055c8de091b8c54aed/Packages/com.headtracked.display/Runtime/ScreenWindowFrame.cs#L75-L121)
- 원본에는 화면 앞뒤의 가림 순서를 실제 렌더로 확인하는 [가림 테스트](https://github.com/lollipop190000/head-tracked-display/blob/960d5de55037a3fe2739ed055c8de091b8c54aed/Packages/com.headtracked.display/Tests/PlayMode/Billboard/BillboardIllusionTests.cs#L112-L169)가 있다. 별도의 [TAA 렌더 테스트](https://github.com/lollipop190000/head-tracked-display/blob/960d5de55037a3fe2739ed055c8de091b8c54aed/Demo/Assets/Tests/PlayMode/SceneSmokeTests.cs#L68-L122)는 각 시점에서 캡처 전 12프레임 동안 렌더하며 이력을 안정화한다. 이는 이번 연속 움직임 테스트의 실행 결과가 아니다. 현재 최소 프레임의 기하 테스트만으로 같은 지각 조건을 검증했다고 볼 수 없다.
- ‘안정된 윤곽/Stable edges’ 또는 TAA를 끄는 비교 옵션의 동작도 다르다. 원본은 4x MSAA를 복원하고, 맨해튼 뷰어는 AA 없음과 1샘플을 사용한다. 이는 기본값이나 이번 검사 전 실제 설정에 대한 진술이 아니며, 두 OFF 라벨을 동일한 렌더 조건으로 보면 안 된다. 이번 합성 A/B 진단은 두 구성을 의도적으로 TAA OFF와 1샘플로 맞췄다. [원본 OFF 전환 검증](https://github.com/lollipop190000/head-tracked-display/blob/960d5de55037a3fe2739ed055c8de091b8c54aed/Demo/Assets/Tests/PlayMode/SceneSmokeTests.cs#L113-L115), [맨해튼 AA 설정](https://github.com/lollipop190000/manhattan-headtracked-viewer/blob/df12acb183746aab50af6c48c728923edfce828b/ManhattanViewer/Assets/Scripts/AfternoonRenderProfile.cs#L19-L61)

챔버는 가까운 기준면과 겹침, 원근, 그림자를 함께 제공한다. 최소 프레임은 이 단서들을 줄인다. 어느 쪽이 사람에게 더 잘 작동하는지는 아직 가설이다. 이번 A/B는 두 클래스를 각각 그대로 사용하는 전체 구성 비교였고 **가상 개구부와 프레임 점유 면적의 차이도 비교 대상에 포함**했다. 후속 도시 비교에서는 물리적 표시 영역, 눈 위치, 공통 도시 기하, 조명 설정, 해상도, AA를 유지한다. 특정 단서의 원인을 찾을 때는 개구부를 같게 맞추거나 벽·바닥, 주변부, 그림자를 하나씩 분리한다.

## 사람이 사용하는 깊이 단서

### 영상의 이동량보다 단서의 일관성이 중요하다

운동 시차는 가까운 것과 먼 것의 상대적 영상 변화다. 전체 도시가 크게 움직이는 것과 깊이 차이가 잘 보이는 것은 같은 지표가 아니다. 특히 먼 물체끼리는 절대 이동량이 비슷할 수 있다.

깊이 해석에는 영상 움직임뿐 아니라 눈의 추적 운동과 관련된 정보도 관여한다. 한편 원근 변화만으로 깊이 방향을 구분할 수 있는 조건도 보고됐다. 따라서 머리 이동량이나 눈의 추적 신호 중 하나를 유일한 해석 원리로 단정하지 않는다. 일반 웹캠의 얼굴 추적으로 실제 망막 운동이나 눈의 추적 운동을 측정했다고 주장해서도 안 된다. [Nawrot와 Stroyan 2009](https://pmc.ncbi.nlm.nih.gov/articles/PMC2735858/), [Rogers 2016](https://journals.sagepub.com/doi/10.1177/0301006616655816)

### 겹침과 표면 변화가 움직임을 뒷받침해야 한다

- 앞 물체가 뒤 물체를 가리고, 고개를 움직이면 뒤 표면이 자연스럽게 드러나는지 확인한다.
- 도로와 창문의 반복 무늬, 물체 크기, 원근 변화가 같은 공간 스케일을 가리키는지 확인한다.
- 그림자는 표면에 붙어 안정적으로 유지되는지, 반사와 하이라이트는 의도한 재질 및 시점 변화와 맞는지 검사한다.
- 화면 앞에 있다고 표현한 물체가 화면 가장자리에 잘리면 가림 관계가 충돌할 수 있다. 첫 진단은 화면 뒤쪽 배치로 단순화하고 앞쪽 배치는 별도로 검사한다.

동적 가림과 상대 운동은 서로 영향을 주며, 단서 하나를 더했다고 언제나 깊이감이 늘어나는 것은 아니다. [Yoonessi와 Baker 2013](https://pubmed.ncbi.nlm.nih.gov/24130259/)

### 평면 화면의 한계는 정확히 구분한다

이 뷰어는 하나의 영상을 양쪽 눈에 보여 준다. 운동 시차에 의한 깊이감은 가능하지만, 가상 장면에 맞는 서로 다른 좌우 눈 영상을 제공하는 양안 입체시는 만들지 않는다. 눈의 초점 조절과 화면 자체의 양안 단서는 여전히 물리적 화면을 가리킨다. 화면 표면에 대한 정보는 그림을 해석하는 방식에 영향을 줄 수 있다. [Vishwanath 등 2005](https://pubmed.ncbi.nlm.nih.gov/16172600/)

이를 곧바로 입체 디스플레이의 전형적인 조절·폭주 불일치로 부르면 부정확하다. 일반적인 단일 영상에서는 초점과 양안 대응이 대체로 같은 화면을 가리킨다. 최종 평가는 평소처럼 두 눈을 뜬 상태를 기준으로 한다.

## 1 실제 표시 영역과 눈 위치를 먼저 확인한다

투영에 사용할 치수는 렌더가 실제로 표시되는 물리적 영역과 일치해야 한다. 합성 입력 검사가 정상이어도 이 대응이 틀리면 실제 관찰자에게 잘못된 시점이 제공될 수 있다. 현재 우선 확인할 항목이다. [프로젝트의 물리적 화면 보정 설명](https://github.com/lollipop190000/head-tracked-display/blob/960d5de55037a3fe2739ed055c8de091b8c54aed/docs/rendering.md#match-the-physical-display-first)

- 렌더가 표시되는 영역의 물리적 폭·높이와 화면 내 위치
- 운영체제 배율, Unity 표시 영역, 렌더 해상도의 관계
- 화면 좌표계와 웹캠 좌표계의 관계
- 눈의 기준 위치와 시선 거리 보정
- 얼굴 중심점과 실제 눈 위치의 차이, 고개 회전 때 생기는 눈 위치 변화

각 값은 해당 설치에서 확인하되 공개 보고서에는 개인별 보정값을 싣지 않는다. 합성 카메라 테스트는 입력 좌표가 맞다고 가정하므로, 실제 눈 위치 추정까지 보증하지 못한다.

**기록:** 보정 전후 기준점 오차, 라이브 추적의 축별 흔들림, 추적 신뢰도, 실제 머리 이동 범위. 추가 하드웨어 없이 확인할 수 없는 절대 정확도는 추정값과 구분한다.

## 2 가까운 기준면의 효과를 실제 도시에서 분리한다

**후속 검사:** 큐브 진단을 실제 도시로 확장한다. 동일한 합성 눈 위치와 카메라 궤적을 두 구성에 적용하고 도시의 배치와 스케일은 유지한다.

- 물리적 표시 영역과 눈 좌표 기준을 맞춘다. 전체 구성 비교에서는 각 클래스의 가상 개구부와 프레임 범위를 유지하고, 단서 분리 검사에서는 개구부를 같게 맞췄는지 명시한다.
- 같은 해상도, 노출, AA, 도시 재질과 조명으로 비교한다.
- 화면 평면, 가까운 물체, 먼 물체의 기준점을 같은 방식으로 표시한다.
- 좌우·상하·앞뒤 시점에서 물체 순서, 잘림, 프레임 정합, 드러나는 표면을 검사한다.

**기록:** 기준점의 예상 위치 대비 픽셀 오차, 물체 쌍의 상대 이동량, 가림 및 잘림 오류의 프레임 번호, 프레임 시간.

**판정 범위:** 렌더 구성의 차이와 오류를 확인한다. 챔버가 사람에게 더 깊게 보이는지는 이 단계에서 판정하지 않는다.

## 3 실제 도시와 라이브 추적의 연속 움직임을 검사한다

**후속 검사:** 정지 → 느린 이동 → 빠른 이동 → 방향 반전 → 정지의 재현 가능한 궤적을 실제 도시에서 실행한다. 좌우, 상하, 앞뒤 축을 분리하고 이후 결합한다. TAA 인과 비교에서는 눈 위치뿐 아니라 시간열도 같게 재생한다. 이후 실제 웹캠으로 추적 안정성을 확인한다.

| 검사 | 제안하는 공학 지표 | 해석의 한계 |
| --- | --- | --- |
| 정지 입력 | 렌더 기준점의 RMS와 p95 흔들림 | 웹캠의 실제 오차나 사람의 감지 여부를 대신하지 않음 |
| 필터 | 입력 대비 진폭 비율, 지연, 반전·정지 뒤 잔여 이동 | 덜 흔들린다고 항상 더 좋은 것은 아님 |
| 프레임 흐름 | 프레임 시간 p50·p95·최댓값, 누락·반복 프레임 | 평균 FPS만으로 반응성을 판정할 수 없음 |
| TAA OFF와 ON | 얇은 경계와 가림 해제 영역의 잔상 지속 프레임 수, 잔상 대비 | 안정화 후 캡처로 연속 움직임 품질을 대신할 수 없음 |
| 추적 중단 재현 | 재획득 때 위치 불연속, 복귀 시간 | 실제 웹캠 환경은 추가 검사가 필요함 |

필터는 흔들림 감소와 지연을 함께 평가한다. 현재 패키지의 [`AdaptiveEyeFilter`](https://github.com/lollipop190000/head-tracked-display/blob/960d5de55037a3fe2739ed055c8de091b8c54aed/Packages/com.headtracked.display/Runtime/AdaptiveEyeFilter.cs#L5-L34)는 이미 속도에 따라 평활 정도를 조절하는 One Euro 방식이다. 새로 도입할 기능으로 간주하지 않고, 기존 필터의 설정과 실제 응답을 비교한다. 이 방식의 사용 자체가 지각적 성공을 보장하지 않는다. [Casiez 등 2012](https://github.com/casiez/OneEuroFilter/blob/main/README.md)

TAA를 검사할 때는 현재·이전 프레임의 투영 변화와 모션 벡터가 맞는지 함께 본다. Unity는 잘못되거나 누락된 모션 벡터가 잔상과 흐림을 일으킬 수 있다고 명시한다. [Unity 6000.3 공식 모션 벡터 문서](https://docs.unity3d.com/6000.3/Documentation/Manual/urp/features/motion-vectors-troubleshooting.html)

**지연 표기:** 포즈 수신부터 렌더 제출까지의 시간은 pose-to-render로 구분한다. 실제 머리 움직임부터 화면 발광까지인 motion-to-photon에는 카메라 노출, 버퍼링, 화면 주사 등이 더 포함된다. 현재 장비와 로그가 직접 측정하지 못하는 구간은 미측정으로 남긴다. 합성 입력이나 화면 녹화를 전체 지연의 직접 측정값으로 표기하지 않는다.

## 4 짧은 사용자 A/B로 지각을 직접 평가한다

**권장 구성:** 짧은 연습 뒤 약 10~15분의 탐색적 비교를 한다. 조건 이름을 숨기고 순서를 무작위화하거나 AB와 BA를 균형 있게 배치한다. 편안한 범위의 움직임만 사용하고 불편하면 멈춘다.

| 조건 | 주변 구성 | 시점 갱신 |
| --- | --- | --- |
| A | 원본 챔버 | 라이브 헤드 트래킹 |
| B | 최소 프레임 | 라이브 헤드 트래킹 |
| C | 원본 챔버 | 기준 시점 고정 |
| D | 최소 프레임 | 기준 시점 고정 |

도시, 초기 시점, 물리적 표시 영역, 머리 이동 배율, AA는 공통으로 유지한다. 깊이 판단에 사용할 물체 쌍은 두 구성에서 모두 충분히 보이도록 고른다. 한 조건에서 가려진 물체의 오답을 깊이 지각 실패로 세지 않는다. 조건별 실제 이동 범위와 추적 품질도 기록한다. 이는 한 사용자의 구현 진단이며, 일반 인구의 지각 성능을 검증하는 실험은 아니다.

### 서로 다른 세 가지 결과를 따로 기록한다

1. **깊이 순서:** 표시한 두 물체 중 어느 것이 더 가까워 보이는지 선택한다. 좌우 위치와 정답을 균형 있게 바꾼다. 조건별 정답 수·시행 수·확신도를 기록한다. 순서만 맞힌 결과를 깊이 크기까지 맞혔다고 해석하지 않는다.
2. **상대 깊이 맞추기:** 검사 전용 기준 물체 쌍의 간격을 조절해 목표 쌍과 같은 깊이 차이로 느껴지는 지점을 찾는다. 도시 전체는 변경하지 않는다. 반복 측정의 중앙값과 변동을 기록한다. 원근 크기 등 다른 단서가 정답을 대신하지 않도록 기준 자극을 통제한다. 검사 UI가 준비되지 않았다면 이 항목은 미실시로 남긴다.
3. **장면 흔들림:** 고개를 움직일 때 공간이 바깥에 고정돼 보이는지, 머리를 따라 미끄러지거나 방향 전환 뒤 뒤늦게 따라오는지 답한다. 같은 문구의 평정과 어느 조건이 더 안정적인지의 선택을 함께 기록한다. 이것은 물체 순서 과제와 별개의 결과다.

소규모 시작안으로 조건별 균형 잡힌 깊이 순서 12회, 상대 깊이 맞추기 3회, 짧은 움직임 블록 뒤 안정감 응답을 사용할 수 있다. 횟수는 탐색적 진단을 위한 제안이며 검증된 최소 표본 수가 아니다. 두 선택지의 깊이 순서 과제는 우연 정답률이 50%지만, 적은 시행의 점수만으로 통과를 선언하지 않는다.

## 결과에 따라 다음 결정을 내린다

- **챔버에서만 좋아진다:** 가까운 기준면과 가림 단서의 역할을 분리해서 검사한다. 도시 축소를 먼저 하지 않는다.
- **연속 궤적에서 잔상이나 튐이 보인다:** 필터, 모션 벡터, AA와 프레임 흐름을 먼저 고친다.
- **합성 입력은 정상인데 라이브에서 흔들린다:** 실제 보정, 추적 오차, 지연을 우선 조사한다.
- **깊이 순서는 맞지만 깊이 차이가 작게 느껴진다:** 순서와 깊이 크기의 차이를 그대로 보고하고, 기준 자극 및 장면 단서의 영향을 확인한다.
- **픽셀 검사는 통과하지만 사용자는 평면이나 미끄러짐을 느낀다:** 기하 검증 통과와 지각 검증 미확인을 함께 기록한다.

현재 숫자에서 모든 사람에게 적용되는 픽셀·지연·평정 합격선을 만들지 않는다. 공학적 회귀 기준과 실제 사용자 비교 결과를 분리해 기록한 뒤, 이 뷰어의 사용 목적에 맞는 수용 기준을 정한다.
